Pillar 1: Persistent HTTP Connection Architecture

Solving the 3-Way Handshake Explosion

In HTTP/1.0 (Non-Persistent), every single resource (HTML, 10 CSS files, 15 JavaScript bundles, 16 images) forces a separate TCP 3-way handshake (SYN → SYN-ACK → ACK) plus TLS negotiation and TCP connection teardown (FIN → ACK).

Total Latency (Non-Persistent) = N × (2 × RTT + TLS_RTT) + Data_Transfer_Time
Total Latency (Persistent HTTP/2) = 1 × (RTT + TLS_RTT) + Stream_Multiplexing_Time

Pillar 2: Multi-Tier Web Caching

Browser, ETag, and CDN Edge Offloading

During admission registration, 90% of page weight comes from static files (University logo, campus banners, CSS, JavaScript libraries, PDF guidelines) that rarely change. Multi-tier caching prevents millions of unnecessary database and web server hits.

1. Browser Cache (Local Disk/RAM)

Cache-Control: public, max-age=31536000, immutable → 0 ms instant load from memory without touching network.

2. Edge CDN Cache (Closest PoP)

ETag: "64f9b-192a" / If-None-Match → 304 Not Modified (50-byte header, 0-byte payload).

3. Origin Application Server

Only dynamic APIs (e.g. /api/check-merit-rank) hit the origin database.

Pillar 3: Reverse Proxy & Load Balancing

Shielding Origin Servers from Concurrency Storms

A Reverse Proxy (e.g., Nginx, HAProxy) sits in front of backend admission microservices to perform:

  • Load Balancing: Distributes incoming applicants using Round-Robin, Least-Connections, or IP-Hash algorithms.
  • SSL/TLS Offloading: Handles expensive cryptographic handshakes at the edge so backend app nodes focus 100% CPU on admission business logic.
  • DDoS & Rate Limiting: Throttles malicious scraping of admission merit lists.
  • Connection Buffering & Keep-Alive Pooling: Shields slow client networks from consuming backend worker threads.
Pillar 4: Cookie Optimization & Session Security

Eliminating Header Bloat & Securing Sessions

By default, browsers attach all cookies matching a domain to every single request—including images, fonts, and scripts that don't need authentication!

The Upstream Bandwidth Multiplication Effect

If cookie payload is 4 KB, and a page has 50 assets requested by 25,000 students:

4 KB × 50 assets × 25,000 students = 5,000,000 KB ≈ 5.0 GB of wasted header traffic!
Solution 1: Cookie-Free Static Domain

Serve static assets from static.college-cdn.com. Browsers will never attach admission session cookies to static requests.

Solution 2: Minimal JWT Tokens

Replace bloated server session cookies with compact 180-byte HMAC tokens containing only essential student ID.

Solution 3: Security Flags

Enforce HttpOnly; Secure; SameSite=Strict to completely prevent XSS session hijacking and CSRF attacks during admission fee payment.

Pillar 5: Efficient Communication & Payload Compression

Gzip, Brotli, and Modern Asset Bundling

Text-based assets (HTML, JSON APIs, CSS, JavaScript) contain redundant syntax that can be compressed dynamically on-the-fly before transmission across the network.

1. Executive Summary & Problem Formulation

During annual admissions, college web servers experience extreme traffic spikes of up to 50,000 simultaneous student visits within hours. Under traditional unoptimized web architectures, the portal suffers from debilitating slow-downs, 14.6s latency, and server crashes (504 Gateway Timeouts). This project investigates the root architectural bottlenecks and presents a comprehensive 5-pillar solution designed for modern production deployment.

2. Root Cause Investigation Matrix

Bottleneck Area Root Cause in Legacy System PBL-8 Recommended Engineering Solution Measured Impact
1. Connection Overhead HTTP/1.0 Non-Persistent connections require a separate TCP 3-way handshake and socket teardown for every asset. Implement HTTP/2 or HTTP/3 with single-connection multiplexing and HPACK header compression. -97% connection overhead; handshakes reduced from 42 to 1.
2. Cache Invalidation Origin servers forced to dynamically re-serve unchanged static assets (logos, campus photos, JavaScript bundles) on every request. Deploy Multi-Tier Caching: Browser Cache with max-age=1y, immutable + CDN Edge Reverse Proxy + ETag conditional validation (304). 92% origin server offload; eliminates unnecessary database lookups.
3. Server Single Point of Failure Single monolithic Apache/PHP origin server overwhelmed by TCP SYN queues and SSL encryption calculations. Deploy Nginx Reverse Proxy with Round-Robin / Least-Connections Load Balancing across 4 worker nodes + SSL Termination. Server CPU drops from 99.8% to 14.5%; 0 downtime.
4. Cookie Header Bloat Unnecessary 4KB tracking & session cookies transmitted on every static image and CSS request. Establish Cookie-Free CDN static domains (static.college-cdn.com) and lightweight 200B signed JWTs with HttpOnly, Secure, SameSite=Strict. Saves 5.0 GB of redundant upstream network bandwidth per 25k users.
5. Payload Transmission Uncompressed HTML, CSS, JavaScript, and unoptimized high-res PNG images sent raw over wire. Enable Brotli / Gzip compression + JavaScript bundle minification + WebP image format conversion. Payload reduced from 14.8 MB to 1.4 MB (90.5% reduction).

3. Mathematical Latency Formulation

Legacy HTTP/1.0 Page Latency:

T_{legacy} = \sum_{i=1}^{N} \Big( 2 \cdot RTT_{TCP} + RTT_{TLS} + \frac{Size_{raw} + Cookie_{bloated}}{Bandwidth} + T_{proc} \Big)

Optimized PBL-8 HTTP/2 + CDN Latency:

T_{opt} = \Big( 1 \cdot RTT_{TCP} + 1 \cdot RTT_{TLS} \Big) + \frac{Size_{compressed}}{Bandwidth} + (1 - CacheHitRate) \cdot T_{origin\_proc}
